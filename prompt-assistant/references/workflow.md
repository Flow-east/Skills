# 协作方法

## 输入状态决定工作方式

| 输入 | 工作重点 | 可观察的完成标准 |
| --- | --- | --- |
| 一句想法 | 明确产物用途，补充决定成败的信息 | 不懂术语的人也能给出关键偏好并拿到成稿 |
| 已有 Prompt | 找实际缺口，保留已清楚的部分 | 原意、事实、约束与技术字面量不被替换 |
| 多轮对话 | 提取已确认信息和纠正，形成独立任务说明 | 新工具无需读旧对话就能理解任务 |
| 换目标工具 | 核对输入、输出和工具能力 | 不携带旧工具不支持的参数，不丢参考素材 |
| Prompt 加失败结果 | 从可见偏差诊断原因，局部修订 | 说明具体改动解决什么，已满意部分保留 |
| 不知道怎样问 | 把专业决策翻译成可理解的选择 | 用户无需先掌握框架或技术词汇 |

## 信息缺口

- **事实**：价格、规格、版本、数据不能补造。有材料先读材料，无法获得时留明确占位或询问。
- **偏好**：画面、语气、详细程度可以提供差异明显的选择。参考过往偏好前核对项目与场景。
- **材料**：参考图、源码、文章、品牌指南需要实际提供。清单放在 Prompt 外；正文中正确指明用途。
- **专业表达**：把“质感好一点”转成可执行维度，例如材质、光线、结构细节。自由发挥应围绕用途，不默认堆满所有维度。
- **成功标准**：把“更好”落实为可观察的要求。缺少标准时先提出适合本任务的建议，不能把建议伪装为原始要求。

简单任务无需按表逐项提问。优先解决最可能改变方向的缺口。不要让“不知道用什么工具”的用户先填模型版本、温度和高级参数。

## 保存含义，而非只保存关键词

把已确认信息分为目标、事实、约束、偏好、排除项与尚未决定的选项。这是内部工作清单，默认不输出成表格。

例如用户认为“强模型可以通过多轮沟通和充分上下文获得高质量结果，但某些生成工具仍需要单段 Prompt”。整理后必须保留这个推导，不能缩减为“用户习惯聊天”。

用户说“完整 Prompt 放在幻灯片里给观众看，我只讲用途”，必须保留资料展示与口播的区别，不能把全文变成讲稿，也不能因口播不读而删去全文。

现有 Prompt 已明确文章长度与结构时，不另外添加专家身份、五点分析、强制反思等要求。只要意思清楚，口语表达也可以是最终 Prompt。

## 从对话交付给新工具

先判断目标工具是否能访问当前上下文。需要独立执行时，保留：最终目标、已选方案、有效参考、重要限制、已经失败的相关尝试、交付标准。删除被用户撤回的方向和无关讨论。

对一段 Prompt 无法承载的附件，给出简短材料清单。不要把长文、源码或敏感原文强行塞进成稿；可以明确目标 Agent 应读取的文件和检查路径。

## 诊断失败

比较期望与实际产物，定位到可见偏差：内容缺失、事实错误、风格不符、局部修改越界、动作时序、输出格式、工具执行失败等。区分四种原因：

1. 描述与约束不足：改写相关指令。
2. 材料或上下文缺失：补资料或改交接方式。
3. 工具能力与工作流不匹配：建议换输入形式、拆步骤或调整工具配置。
4. 随机波动或原因未知：保留假设，必要时重复或对照，不能断言增加某个词就有效。

一次优先改最相关的变量，并记录改了什么。用户要求探索多个方向时可以并行提出选项，但不把这当成受控对照。生成任务涉及费用时，测试次数和预算沿用用户授权，不能凭 Skill 自动追加付费生成。
