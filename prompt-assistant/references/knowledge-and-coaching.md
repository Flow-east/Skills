# 知识与随任务学习

这些条目是用于判断和解释的初始知识，不是每次输出的栏目。先完成任务，只在有帮助时教一个相关概念；练习按用户意愿进行。

## K01 上下文可见性

- **问题**：在新工具里说“按之前那个风格”，结果不一致。
- **机制**：目标工具只能利用实际获得的输入与其可访问状态。
- **做法**：整理已确认要求、示例与附件用途，形成可独立理解的任务。
- **小例子**：“左侧留三分之一位置放标题”比“按刚才那张的排版”更可移交。
- **边界**：提示词不能让工具自动获得未上传的文件，也不应复制所有无关历史。
- **来源**：S1、S2。此处的交接清单为本 Skill 的设计。

## K02 目标与验收标准

- **问题**：“帮我做得更好”无法指导改动。
- **机制**：把质量标准落实为能检查的产物特征，可以减少解释分歧。
- **做法**：结合用途提出少量决定性标准，例如信息完整、主体一致、能导入、可运行。
- **小例子**：3D 资产先说用途、观察距离、关键轮廓与导入要求，再讨论几何细节。
- **边界**：标准中事实与用户偏好需要依据；可供选择的建议不是用户既定要求。
- **来源**：S1、S2；具体转译方式为本 Skill 的设计。

## K03 示例与对比

- **问题**：用户说不清语气、风格或格式。
- **机制**：输入输出示例能传递难以用抽象形容词表达的模式。
- **做法**：提供少量差异明确的对比，保留用户选择的原因；结构化任务可用边界示例。
- **小例子**：展示两种开场，一种直接讲经验，一种先讲概念，让用户选择更像自己的表达。
- **边界**：示例需与目标一致，不能把示例事实带入用户任务；简单任务可能无需示例。
- **来源**：S1、S2。

## K04 改动与保持项

- **问题**：优化一句话却换了观点，换衣服颜色却改了人物。
- **机制**：明确变化范围可以帮助目标模型保留已有成果。
- **做法**：定位本次修改对象，保留相关不变量；用结果检查是否越界。
- **小例子**：“保留观点与因果关系，只调整书面感”或“只改背景，保留主体姿态”。
- **边界**：并非列出的保持项都能由工具保证，需要实际查看结果。
- **来源**：S2、S3；具体保持项清单为本 Skill 的设计。

## K05 结构与任务分解

- **问题**：一个复杂任务混在一起，遗漏依赖步骤。
- **机制**：分阶段产物可以让人检查中间结果并及时纠正。
- **做法**：只有存在真实依赖、检查点或工具边界时才分解，清楚说明每步交付物。
- **小例子**：先确定角色参考，再做多个镜头，最后检查角色一致性。
- **边界**：简单任务无须复杂流程；固定长推理链或角色扮演不会自动提高质量。
- **来源**：S1、S2、S4。

## K06 材料、工具与 Prompt 的分工

- **问题**：不断加形容词仍得不到精确结构或最新资料。
- **机制**：效果受输入材料、可用工具、模型能力、参数和任务组织共同影响。
- **做法**：先定位瓶颈。缺参考补参考，缺检索能力调整工具，局部编辑使用支持的编辑机制。
- **小例子**：一张参考图可能比继续增加“高级感”的近义词更有帮助。
- **边界**：这是诊断方向，不保证添加材料就能解决所有能力限制。
- **来源**：S2、S3、S4。

## K07 反馈与对照

- **问题**：一次偶然成功，就认为某个词总有效。
- **机制**：同时改变多个条件无法确定哪个因素起作用，生成本身也有波动。
- **做法**：记录实际偏差和关键变量，必要时固定工具与输入对照两版，并在另一个任务复用检查。
- **小例子**：保留同一参考图与模型，比较只改变镜头描述的两版。
- **边界**：小样本只支持有限范围的经验。用户偏好与客观正确性分开评估。
- **来源**：S5；两任务的个人方法启用门槛是本 Skill 的工程选择。

## K08 个人记忆与适用范围

- **问题**：某次选择被固化成永久偏好，助手越来越刻板。
- **机制**：偏好、经历和方法承担不同作用，需要来源、范围和更新条件。
- **做法**：以项目、操作场景和工具界定记忆，当前要求覆盖旧默认。相关条目按需读取。
- **小例子**：“本账号封面不放文字”不限制另一个客户的促销海报。
- **边界**：更长的历史和更多收藏不自动带来更好的判断。
- **来源**：S6、S7。

## 教学方式与学习记录

默认采用“成稿 + 一个有用的小提示”，小提示仅在能帮助用户下次表达时出现。用户只要成稿时省略。用户追问可展开：原理、一组对比、适用范围与自愿练习。

把知识映射为稳定键，如 `context.handoff`、`visual.edit-invariants`、`evaluation.controlled-comparison`。记录范围和证据：

- `introduced`：本次已经解释，不代表用户理解。
- `understood`：用户明确表示理解，或用自己的话正确解释。
- `applied`：在新情境中正确使用，有可见实例或具体用户报告。

发现误解时可降低记录阶段，并说明具体概念需要补充。不要累计“能力分数”，也不要每次测验用户。全局关闭教学用工具设置，单次“不要解释”只影响当前任务。
