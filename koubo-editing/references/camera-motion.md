# 镜头运动：景别状态与语义决策

## 参考与判断
有用户参考时先覆盖全片抽样，再对景别切换区间密集取帧；几张相同景别截图不能推断全片幅度。需要分辨背景同步缩放与人物前倾。样本有快速切近再保持，不能把“丝滑”等同于“小幅度、慢动作”，也不能把所有转场都变成机械推近后退回。

模板 `camera_recipe` 绑定普通/中近/近景倍率，以及 punch（快速切近）、glide（缓推）、reframe（构图转换）、cut（明确硬切）的时长。它们是原创可调参数，不是测得开拍内部值。幅度按头顶、脸部、手势与源清晰度复核；只要要求安全，就把所有镜头压成微缩放，也不算完成。

## 编译：先定内容，再定镜头
使用 `camera_motion.build_track(duration, decisions, recipe, anchor)`：
```python
recipe = get_template('orange_hook')['camera_recipe']
track = build_track(final_duration, [
    {'start': 4.0, 'level': 'close', 'kind': 'punch', 'reason': '反转句落点'},
    {'start': 10.0, 'level': 'normal', 'kind': 'reframe', 'reason': '进入解释段'},
    {'start': 15.0, 'level': 'medium', 'kind': 'glide', 'reason': '长句收束'}
], recipe, anchor=[0.5, 0.42])
plan['camera_motion'] = track
```
时间均为最终成片秒，不是源片秒；每项可用 `zoom`、`duration`覆盖默认值。每个状态持续到下一项决策，没有自动退回、没有每段重置。重叠、乱序、越过总时长或超出计划 max_zoom 会报错。改变内容取舍后必须重新映射节点，即使总时长相同也不能直接沿用。

- 自动分析仅输出中性基线，并标注镜头待编排；不能把 ASR 停顿当作近景触发证据。Codex 按全文语义作者决策。
- 五次缓入缓出在运动两端速度/加速度归零，punch/glide用不同时长。cut是明确的硬切，只有作者选择它才出现；不是声称所有镜头变化都数学连续。
- `keyframes` 中 `transition` 描述进入该节点的方式：`smootherstep` 或 `cut`。同倍率两节点表示停留。
- 顶层 `max_zoom` 默认为1.15；更大幅度要显式声明，最高允许1.35，不代表1.35适合每条视频。复核最紧景别，必要时降低单个镜头或调整固定anchor，不能切头、压脸。
- 固定 anchor 是画面稳定点，不要每帧跟随检测抖动。浮点裁切+Lanczos重采样减少整数裁切台阶。字幕在镜头变换之后绘制，保持屏幕位置与字号。
- 源片姿势跳变不会被缩放曲线消除；剪辑段切换可保持景别，也可显式设计cut/reframe，但不能无意重置倍率。

## 验收与交付
读 `camera_qa.json` 检查逐帧变化、声明的硬切和源剪切点前后状态；从最终MP4抽查进入/峰值/退出及手势帧。必须有实际动态预览，不能只看峰值截图就宣称衔接等同参考。
只调镜头时，确认字幕文件、音频解码哈希、剪辑映射不变。交付前后同一段同步并排对照，标签写清版本；所有给用户的时间均使用对应成片播放器时间。
