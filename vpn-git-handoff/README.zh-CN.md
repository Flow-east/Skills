# VPN 环境下的 Git 交接

[English](README.md)

这是一个不绑定特定智能体的技能，适用于只能通过全隧道 VPN 访问 Git 远端、且切换 VPN 会导致编程智能体断线的场景。

这套流程将网络切换视为明确的责任边界：

```text
智能体在线
  检查 → 判断 → 测试 → 准备精确的操作卡
                         ↓
用户连接 VPN
  切换网络 → 执行卡片列出的远端命令 → 保存完整输出
                         ↓
智能体重新连接
  检查结果 → 在本地完成整合 → 测试 → 必要时准备下一张操作卡
```

## 支持的工作流程

- 准备并发布本地分支。
- 获取远端状态，再由重新连接的智能体安全地完成合并、变基或快进。
- 将只能通过 VPN 访问的仓库克隆到已经核验的目标目录。
- 处理非快进、身份验证、网络、受保护分支、服务端钩子、Git LFS 或子模块等失败情况。
- 生成适用于具体仓库的人工交接文档。

操作卡会有意排除普通的 `git pull`，因为它将远端数据传输与本地整合合并在一个操作中，可能在智能体断线时产生冲突。

推送操作卡会明确指定远端和目标分支，不依赖本地的 `push.default` 或推送远端配置。

## 用户与智能体的职责边界

| 编程智能体 | 用户 |
| --- | --- |
| 检查仓库并选择 Git 策略 | 连接或断开 VPN |
| 完成已获授权的本地修改、测试、提交、合并和变基 | 只执行操作卡中的精确命令 |
| 给出命令、成功标志和停止条件 | 保存完整的终端输出 |
| 重新连接后核对并处理执行结果 | 遇到停止条件时立即停止并返回 |

用户无需在智能体断线期间临场决定分支策略、解决冲突、强制推送、修改远端配置或更改凭证。

生成操作卡本身并不授权智能体修改或提交代码。如果已经核验的分支、`HEAD`、工作区、远端或目标发生变化，原操作卡立即失效。

## 可移植的技能包

核心技能包遵循开放的 Agent Skills 目录格式：

```text
vpn-git-handoff/
├── README.md
├── README.zh-CN.md
├── SKILL.md
├── references/
│   └── manual-vpn-git-sop.md
└── agents/
    └── openai.yaml
```

`SKILL.md` 和 `references/` 不绑定特定智能体。`agents/openai.yaml` 只是可选的 Codex 界面元数据，其他兼容技能格式的智能体可以忽略它。

## 安装

将完整的 `vpn-git-handoff` 目录复制到编程智能体支持的技能目录中。

安装到个人 Codex 环境：

```bash
cp -R vpn-git-handoff ~/.codex/skills/
```

如果使用的智能体不会自动发现 Agent Skills，可将 `SKILL.md` 作为可复用的指令文件提供给它，并保持 `references/` 的相对路径不变。

## 使用方法

在支持显式调用技能的环境中：

```text
使用 $vpn-git-handoff 为这个仓库准备下一次安全的 VPN Git 交接。
```

自然语言示例：

```text
准备好这个分支，让我只需切换到 VPN 并按照推送操作卡执行。
```

```text
生成一份适用于当前项目的 VPN Git 交接指南。
```

## 适用范围与安全边界

- 适用于任何只能通过 VPN 访问的 Git 远端，不限于 GitLab。
- 不配置 VPN 客户端、代理、分流或系统路由。
- 不在操作卡或文档中暴露凭证。
- 不把合并、变基、冲突处理、强制推送或远端配置等决策交给断线期间的用户。
- 将合并请求、版本发布、服务器拉取和部署视为独立工作流程。
