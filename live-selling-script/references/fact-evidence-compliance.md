## 事实优先级

发生冲突时按以下顺序处理：

1. 用户或产品负责人当前明确确认的事实。
2. 当前产品界面、合同、商品页、交付文件和可重复演示。
3. 官方文档、资质、平台状态和真实记录。
4. 历史话术和内部笔记。
5. 行业经验与竞品信息。

低优先级信息只能提出问题，不能覆盖高优先级事实。历史材料可能过期，当前价格、版本、规则和售后需重新确认。

## 事实状态

- **已确认**：有明确来源，可直接使用，但仍按证据强度控制语气。
- **可合理推断**：能从事实得出，但需要明确这是推断，不包装成承诺。
- **待确认**：影响话术但没有来源，保留占位符或提问。
- **不可使用**：已知错误、超出产品边界、无权承诺或违反规则。

不要把“能做某一步”扩写成“保证获得最终结果”。例如：生成草稿不等于正式发布，提供课程不等于保证就业，搭建工具不等于保证成交。

## 卖点证据链

每个核心卖点至少完成：

`事实 -> 适用条件 -> 用户价值 -> 证据 -> 现场动作 -> 限制`

示例：

| 层次 | 软件示例 |
| --- | --- |
| 事实 | 支持将文章同步到公众号草稿流程 |
| 条件 | 账号授权有效，接口和内容符合要求 |
| 价值 | 减少跨工具复制的步骤 |
| 证据 | 展示授权页、草稿状态和失败记录 |
| 动作 | 现场同步一篇安全样例或展示历史记录 |
| 限制 | 不说自动正式群发或百分百成功 |

## 不同主张的证据要求

### 功能主张

优先使用实际界面、实物操作、说明书或交付清单。未操作过的功能不写成已验证体验。

### 效果主张

说明测试条件、适用范围和个体差异。美妆、健康、教育、收益等结果型主张尤其谨慎。

### 比较主张

比较对象、版本、测试条件和指标必须一致。不得虚构竞品缺陷、假装第三方检测或安排误导性对比。

### 数字主张

效率倍数、节省比例、转化率、销量和用户数量需要来源、口径和时间。没有依据时改成可观察过程，不编一个看起来精确的数字。

### 服务主张

上门范围、响应时间、修改次数、交付周期、售后期限和升级政策以正式协议或当前政策为准。

### 价格与活动主张

原价、直播价、赠品价值、库存、截止时间和适用条件必须真实一致。活动结束后及时更新话术。

### 用户结果主张

区分产品提供的能力与用户最终取得的结果。涨粉、变现、就业、治愈、减重、收益等不得由中间能力直接推出。

## 未知信息处理

按重要程度选择：

1. 影响产品是否适用：停止并询问。
2. 影响价格、权益或承诺：保留 `[待确认：...]`。
3. 只影响风格：提出候选假设并继续。
4. 可通过官方或产品页面确认：先研究，再给来源和日期。

禁止用“行业通常如此”填补本产品的价格、库存、售后、资质和效果。

## 高风险表达

重点检查：

- 绝对化：绝对、百分百、所有人、任何问题、永远不会。
- 极限与地位：全网最低、行业第一、顶级、国家级。
- 无依据结果：一键爆款、买了就涨粉、保证变现、一定有效。
- 虚假稀缺：只有今天、最后几单、下播下架、库存告急，但后台没有对应事实。
- 虚假轻松：零学习成本、完全不用改、什么设备都适用。
- 模糊全流程：把有限流程说成覆盖完整运营、增长、复盘和售后。
- 虚构证言：不存在的用户反馈、销量、评委反应和评论区问题。

不要只做同义词替换来规避审核。核心主张不真实时，应删除或降低承诺，而不是寻找擦边说法。

## 活动与成交边界

- 有活动：写清价格、权益、时间、数量、适用条件和结束方式。
- 没活动：用产品适配、试用、演示、咨询或正常商品动作成交。
- 比赛或面试：不得假装后台库存、真实订单或用户评论存在。
- 高客单产品：优先用评估、预约和交付说明降低风险。
- 软件：根据商业政策选择试用、演示、版本咨询或购买，不默认“库存”。
- 实物：下单动作必须对应真实 SKU、物流、退换和赠品条件。

检查脚本只能发现词语风险；最终责任在产品事实核验、平台当前规则和必要的专业合规审核。
