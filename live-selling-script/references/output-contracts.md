## 共创阶段通用格式

每个阶段保持短而明确：

```markdown
## 当前结论

- 已确认：
- 推断及依据：
- 待确认：
- 本阶段建议：

## 需要你确认

1. 最影响下一步的问题
2. 必要时第二个问题
```

不要把每个字段都变成问题。能从资料中提取的先填写；能给候选项的不要让用户从零回答。

```markdown

- [待确认价格]
- [待确认权益]

## 开播前准备
- 演示材料
- 画面与场控

## 0:00-0:XX 拉新进场
口播正文

[主播动作]
[场控配合]

## 后续五步
...

## 常见异议分支
...

## 下一轮重新进场句
...

## 未确认信息与风险提示
...
```

动作提示与口播必须视觉上分开，避免主播把说明文字念出来。

## 审核模式

按严重度输出：

1. 事实错误或无法兑现的承诺。
2. 核心证据缺失。
3. 人群、平台或成交动作错配。
4. 结构和互动问题。
5. 书面感、重复和口语节奏。

每条问题引用具体原句并说明影响。用户没有要求改写时，不附加新稿。

## 转写整理模式

按以下层次分离：

1. 原始 `.txt` / `.srt` 或忠实转写。
2. 可确认原话。
3. 听不清或需回看的内容。
4. 可读整理稿。
5. 结构分析与评价。
6. 仅在用户要求时提供改写稿。

不得用合理猜测悄悄补齐听不清的品牌名、价格、参数或承诺。
