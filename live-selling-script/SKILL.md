# 共创中文直播成交话术

## 核心原则

把方法和答案分开：固化分析流程、六步循环和验收标准；实时研究具体行业、产品、人群、痛点、平台、证据与权益。

遵守以下顺序：

1. 先研究，再判断。
2. 先确认结构，再写逐字稿。
3. 先证明产品价值，再设计成交动作。
4. 已确认事实优先于行业经验；行业经验优先于猜测；无法确认时保留占位符。
5. 共创不等于反复索要资料。先读取现有文件、链接和历史结论，给出候选判断，再提出最多三个会影响下一阶段的问题。

## 选择工作模式

根据用户意图选择模式，不要机械执行完整流程。

- **共创模式**：默认模式。适合从零策划、产品复杂、信息不完整或用户希望共同讨论。逐阶段输出并等待关键确认。
- **快速成稿模式**：用户明确要求直接出稿，且产品事实较完整。自行完成分析，在开头列出假设和占位符，再给成稿。
- **审核模式**：用户提供现有话术并要求评价、修改或事实核验。先列问题与证据，再按用户要求决定是否改写。
- **转写整理模式**：用户提供视频、音频或转写。先保留忠实原话和不确定处，再单独整理结构、评价或改写，不把润色稿冒充原话。

用户明确限定“只评价”“不要修改建议”“只提取原话”时，严格停在指定边界。

## 阶段式共创流程

### 阶段 0：盘点任务与材料

明确任务类型、产品、目标平台、直播目标、现有素材和交付形式。

先执行可自行完成的工作：

- 搜索用户提供的本地文件、产品说明、历史话术、转写和截图。
- 用户提供网页或当前平台规则相关问题时，浏览并优先使用产品官方、平台官方和监管来源。
- 将产品事实、用户说法、外部资料和自己的推断分开记录。

输出简短任务卡：已知、未知、建议模式、下一步。只有缺少关键材料时才提问。

### 阶段 1：建立产品事实卡

整理：

- 产品是什么，不是什么。
- 核心功能或服务流程。
- 价格、版本、权益、库存、交付、售后和时效。
- 可现场演示或展示的证据。
- 已确认边界和禁止自行补充的内容。

给每条信息标记 `已确认`、`可合理推断`、`待确认` 或 `不可使用`。价格、效果、用户结果、稀缺性和售后不得从品类常识补全。

阶段门：核心产品边界未确定时，不进入卖点写作。

### 阶段 2：共创目标人群与痛点地图

不要停留在人口属性。分析：

- 谁在什么时刻最需要它。
- 他正在完成什么任务。
- 具体卡点、情绪和已有替代方案。
- 不解决的代价和现在行动的理由。
- 购买前最可能提出的异议。

使用品类研究路线作为提问提醒，不把其中的示例当成产品事实。提出一到三个候选主痛点，让用户校正；最终选择一个主痛点和最多两个辅助痛点。

阶段门：不能用一句具体生活或工作场景描述主痛点时，不进入完整结构设计。

### 阶段 3：确定平台、账号阶段和主播声音

把平台基线当作初始假设，不当作固定结论。结合账号现状确定：

- 平台及当前规则。
- 新号冷启动、稳定直播、活动场或私域承接等账号阶段。
- 主播身份、可信来源、说话速度、惯用词和不愿说的表达。
- 专业讲解、朋友聊天、顾问诊断或高能成交等主风格。
- 直播目标：停留、互动、商品点击、直接购买、试用、留资或预约。

阶段门：平台、主播声音和行动路径必须彼此兼容。

### 阶段 4：建立证据、演示、异议与权益地图

为每个核心卖点建立完整链路：

`产品事实 -> 用户价值 -> 可见证据 -> 演示动作 -> 常见异议 -> 回应边界`

优先使用：现场演示、前后对比、实物细节、上游来源、真实流程、资质、合同交付范围和可核验案例。不要用形容词替代证据。

同时明确价格锚点、实际权益、活动截止条件和下一步动作。没有真实活动时，不制造倒计时、库存或“下播下架”。

阶段门：核心卖点至少有一种可见或可核验证据；否则降级表述或删除。

### 阶段 5：共同确定六步结构卡

将前四阶段结论装入六步循环：

1. 拉新进场
2. 痛点信任
3. 方法交付
4. 互动确认
5. 痛点延伸
6. 行动指令

先输出结构卡，不立即扩写。每一步写清：观众状态、目标、核心内容、证据或动作、互动、时长、转场句和风险。

六步逻辑固定，篇幅不固定。根据品类、决策成本和证据形式调整权重。用户确认结构后再进入逐字稿；若用户明确要求直接写，可在标注假设后继续。

### 阶段 6：生成完整直播话术

默认输出一个可循环 5-10 分钟的单品话术，而不是假装写满整场数小时直播。包括：

- 可直接照念的口播。
- `[主播动作]`、`[画面/演示]`、`[场控配合]`。
- 真互动问题和可能的接话分支。
- 异议处理。
- 行动指令。
- 下一轮重新进场句。
- 待确认信息和替换项。

对同一产品需要多轮时，保持六步逻辑，轮换痛点、证据、异议或人群切口，不要只换同义词。

### 阶段 7：事实、口语与成交验收

逐项检查：

- 每个重要卖点能否回到产品事实或证据。
- 是否把草稿、试用、预约等能力夸成最终结果。
- 是否出现无依据数字、绝对承诺、虚假比较或虚假稀缺。
- 是否像真人当场说话，而不是方案说明书、公众号文章或 AI 客服。
- 互动之后是否有接话逻辑。
- 行动指令是否符合产品决策成本。
- 未确认信息是否仍用明确占位符表示。

运行检查脚本：

```bash
python3 scripts/lint_script.py <话术文件>
```

脚本只提供风险提示，不能代替人工事实核验、法律判断或平台当前规则查询。

## 研究与提问规则

- 当前平台规则、价格、商业政策、产品页面和竞品信息可能变化，必要时在线核验并注明来源和日期。
- 用户已有真实材料时，先分析材料，不让用户重复填写问卷。
- 每轮问题控制在一到三个，并同时给出候选判断，便于用户纠正。
- 用户暂时不回答非关键问题时，使用明确假设继续；关键事实缺失时保留占位符，不编造。
- 不把行业常见痛点直接写成“目标用户一定如此”。先作为假设，再用用户资料、评论、访谈、售后问题或公开研究验证。

## 最终质量标准

一份合格话术必须同时满足：

1. **相关**：开场能让明确人群认出自己的具体场景。
2. **可信**：产品事实、主播身份和证据彼此一致。
3. **有用**：成交前至少提供一个真实方法、判断或演示结果。
4. **可见**：核心价值尽量通过动作、画面、数据或来源证明。
5. **可说**：句子适合呼吸和临场接话，不依赖书面长段落。
6. **可转化**：行动指令清楚且与决策成本匹配。
7. **有边界**：未知信息、平台风险和产品限制没有被营销语言掩盖。
